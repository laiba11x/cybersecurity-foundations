# Common Vulnerabilities and Exposures (CVE)

## What is CVE?

**CVE (Common Vulnerabilities and Exposures)** is a system used to give known cybersecurity vulnerabilities a **unique identifier**.

It acts like a **universal dictionary of vulnerabilities**, so security professionals can refer to the same vulnerability using the same name.

### CVE Format

CVE identifiers follow this format:

`CVE-YEAR-NUMBER`

Example:

`CVE-2025-55182`

* **CVE** = Common Vulnerabilities and Exposures
* **2025** = Year the CVE was assigned
* **55182** = Unique number for that vulnerability

## Vulnerability Names

Some serious vulnerabilities are given memorable names, also called **monikers**.

Examples:

* Heartbleed
* Log4Shell
* React2Shell

## CVSS

**CVSS (Common Vulnerability Scoring System)** is used to give vulnerabilities a **severity score**.

The score helps organisations decide which vulnerabilities should be dealt with first.

Factors can include:

* **Impact** – What damage could the vulnerability cause?
* **Complexity** – How difficult is it to exploit?
* **Availability** – How likely is the vulnerability to be exploited?

Organisations can use these scores to **prioritise the highest-risk vulnerabilities first**.

## ExploitDB and PoCs

**ExploitDB** contains information about known vulnerabilities and exploits.

A **PoC (Proof of Concept)** is a script or demonstration that shows how a vulnerability can be exploited.

## Key takeaway

**CVE = unique identifier for a known vulnerability.**

**CVSS = severity score used to help prioritise vulnerabilities.**

**PoC = demonstration of how a vulnerability can be exploited.**
